## スライド 2：T1. パッチコア継続学習のメモリ解放処理確認・修正

- **担当**：Speaker 1
- **優先度**：高
- **期限**：2026-05-28
- **背景／目的**：1 プロセス内で継続学習ループを回したため特徴量バンクが累積し、2,000枚×8回目で OOM。原因の切り分けと最小修正で 9 回目以降まで通せる状態にする。

**アウトプット形式**（事前に明示）：
1. **コード差分**：`src/patchcore/` 配下の該当ファイル。PR or コミット URL を結果欄に記載。
2. **メモリ使用量グラフ**：図 T1-1
   - 横軸：継続学習ラウンド番号（1〜N）
   - 縦軸：プロセス常駐メモリ（GB）
   - 凡例：「修正前」「修正後」
   - 保存先：`results/memory_profile/round_vs_rss.png`
3. **完走確認ログ**：2,000枚×N 回が落ちずに完了したログの末尾抜粋（5 行程度）。

**計画**：
- [x] 継続学習スクリプトで `del` / `torch.cuda.empty_cache()` / `gc.collect()` の挿入箇所を洗い出す → **現状ゼロ**を確認（`bin/run_continual_learning.py` を grep）
- [x] 1 ラウンド毎のメモリ計測 → 既に [run_continual_learning.py:50-59](../../bin/run_continual_learning.py#L50-L59) の `get_memory_mb()` が `/proc/self/status` の VmRSS を読み，`results.csv` の `memory_mb` 列として保存済み．`tracemalloc` 追加は不要．
- [ ] 修正候補の挿入箇所（次節「現状調査結果」参照）に `del` / `gc.collect()` を入れ，2,000枚×10 回以上の完走を確認

**現状調査結果**（実装側）：
- `bin/run_continual_learning.py` 内に `gc` / `del` / `torch.cuda.empty_cache` / `tracemalloc` は **0 件**．
- ラウンド毎の累積要因（実測 RSS の増分から推定）：
  1. `new_features_list`（パッチ特徴のバッチ毎リスト）と `new_features = np.concatenate(...)` がラウンド中だけで数 GB 規模．スコープを抜けても GC 起動契機が無く RSS に居残る．
  2. `pc.anomaly_scorer.fit(detection_features=[merged])` 時に **旧 faiss index と新 index が一時的に同居**．`merged = np.concatenate([old, new_coreset])` の `merged` も保持される（最大ケースで 1.7M ベクトル × 1024dim × 4byte ≒ **7GB**）．
  3. `pc.predict(test_loader)` 経由でスコア配列が CPU 側に保持される．

**修正案（最小差分）**：
- 各ラウンド末尾で `del new_features_list, new_features, new_coreset, merged, scores, labels_gt` → `gc.collect()` → `torch.cuda.empty_cache()` を順に呼ぶ．
- `import gc` を追加．
- 念のため，`pc.anomaly_scorer.fit()` 直後に旧 `detection_features` への参照を解放してから faiss index を再構築する順序に変える．

**結果**（埋める）：
- メモリ使用量（修正前）：8 ラウンド時点で RSS **33.3GB**（results/ContinualLearning/20260526_042950/results.csv，2,000枚×10%）．増分はほぼ線形（≒ 1.8GB / ラウンド）．
- 図 T1-1：「修正前」曲線は既存 CSV から即描ける（`memory_mb` 列）．「修正後」は修正コミット後に取得．
- 完走可否：未確認（修正コミット後に実施）

**ステータス**：☐ 未着手　☑ 進行中　☐ 完了　☐ ブロック
